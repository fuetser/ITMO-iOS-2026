# Lab6 — QuoteOfTheDay

Приложение на SwiftUI: случайные цитаты из сети, сохранённая цитата дня
в UserDefaults и избранное с заметками в SwiftData.

## Как читать проект

1. `Models/Quote.swift`: цитата — идентификатор, текст и автор.
2. `Repositories/QuoteRepository.swift`: запрос одной цитаты, обработка ошибок,
   повторы и преобразование серверного ответа в `Quote`.
3. `ViewModels/QuoteViewModel.swift`: действия главного экрана. Начать с
   `loadInitialQuote()` и `fetchNewQuote()`.
4. `Views/ContentView.swift`: подготовка зависимостей и готовый `QuoteScreen`.
   Затем прочитать `FavoritesView`, `EditFavoriteView` и `FavoritesViewModel`.
5. `Storage`: `QuoteOfTheDayStorage` сохраняет цитату дня, `FavoritesService`
   работает с избранным в SwiftData, `AppServices` предоставляет зависимости экранам.

`QuoteOfTheDayApp` — точка входа. Он создаёт контейнер SwiftData и `AppServices`.
При ошибке открытия базы вместо приложения показывается сообщение с причиной.

## Простая схема работы с сетью

**QuoteViewModel → QuoteRepository → URLSessionQuoteTransport → DummyJSON**

Каждый вызов `randomQuote()` запускает новую сетевую операцию:

```http
GET https://dummyjson.com/quotes/random
Accept: application/json
```

[Endpoint случайной цитаты](https://dummyjson.com/docs/quotes) возвращает один объект:

```json
{
  "id": 1,
  "quote": "Life isn't about getting and having, it's about giving and being.",
  "author": "Kevin Kruse"
}
```

Сервер выбирает цитату; повтор текущей цитаты допустим. Приложение больше не загружает
весь каталог, не сохраняет его в памяти или файле, не отслеживает срок свежести
и не запускает фоновое обновление. Старый файл каталога больше не используется.
HTTP-кеш URLSession также отключён.

`QuoteRepository` — обычный неизменяемый класс. `AppServices` передаёт его экранам,
но каждый запрос выполняется независимо: общих задач загрузки и cooldown между
вызовами нет. Отмена экрана отменяет его HTTP-операцию, не затрагивая другие окна.

### От кнопки до результата

1. «Другая цитата» вызывает `startAction`, который запоминает задачу экрана.
2. `QuoteViewModel.fetchNewQuote()` блокирует повторное действие и включает `isLoading`.
3. Репозиторий отправляет GET, проверяет ответ и декодирует одну цитату.
4. Модель проверяет отмену, обновляет `currentQuote`, сохраняет цитату дня
   и проверяет статус избранного.
5. SwiftUI замечает изменения наблюдаемой модели и обновляет экран.
6. `defer` выключает `isLoading` при любом выходе из метода.

При закрытии экрана задача отменяется. Отмена не показывается пользователю как ошибка.

### Что остаётся доступным без сети

Сохранение цитаты дня в UserDefaults сохранено отдельно от сетевого слоя:

- При открытии приложения сегодняшняя цитата показывается без запроса к серверу.
- Если запрос завершился ошибкой, модель пробует показать ранее сохранённую цитату.
- Если сохранённой цитаты нет, экран показывает сообщение об ошибке и кнопку повтора.
- Если новая цитата получена, но сохранить её не удалось, она остаётся на экране
  с предупреждением о локальном сохранении.

Выбирать новые цитаты без сети больше нельзя. Избранное и заметки остаются в SwiftData.
Формат этих данных и алгоритм преобразования серверного ID в стабильный UUID сохранены.

### Проверки и ограничения

| Настройка | Значение |
|---|---|
| Успешный ответ | HTTP 200 и `application/json`, включая параметры charset |
| Размер ответа | Не более 64 КиБ; проверяется во время приёма данных |
| Содержимое | Положительный ID в прежнем диапазоне, непустые текст и автор |
| Таймаут отсутствия данных | 10 секунд |
| Общий бюджет сетевой операции | 20 секунд вместе с повторами и задержками |
| Число попыток | Максимум три на один вызов |
| Задержки повторов | Случайные `0…0,5` и `0…1` секунды, с учётом Retry-After |

Повторяются только таймаут, обрыв соединения и HTTP 408, 429, 500, 502, 503, 504.
Отмена, отсутствие интернета, ошибки сертификата, остальные статусы и некорректные
данные не повторяются.

Retry-After разбирается как число секунд или HTTP-дата. Если ожидание не помещается
в оставшийся бюджет, операция возвращает ошибку. Новая операция начинается по новому
действию пользователя; запрет до Retry-After между разными вызовами не хранится.

Репозиторий разделяет создание запроса, загрузку одной попытки, проверку статуса,
декодирование и ожидание повтора. Разбор Retry-After вынесен в `RetryAfterParser`.

HTTP-транспорт читает тело через `URLSession.bytes(for:delegate:)` и `AsyncBytes`.
Ограничение размера проверяется во время чтения, отмена прерывает всю сессию запроса.
Ручных continuations и delegate-методов получения данных больше нет. Два метода
`urlSession` остаются для проверки перенаправлений и сбора метрик: их имена и
сигнатуры задаёт протокол `URLSessionTaskDelegate`. Разрешены только
HTTPS-перенаправления на тот же хост и стандартный порт без userinfo.
Стандартные проверки TLS и ATS сохранены. Cookies и хранилище credentials отключены.

Логи используют subsystem `com.fuetser.QuoteOfTheDay`, категории `HTTP` и `QuoteRepository`.
Записываются номер попытки, статус, размер, длительность и категория ошибки.
Тексты цитат, заметки и тела ответов не журналируются. Внешнего сервиса аналитики нет.

DummyJSON предоставляет данные для тестирования и прототипирования. Надёжность
провайдера остаётся внешним ограничением; собственный backend здесь не создаётся.

## Коротко о конструкциях Swift

| Конструкция | Назначение в проекте |
|---|---|
| `@State` | Сохраняет принадлежащее экрану состояние: модель, открытую модалку и задачу |
| `@Observable` | Делает изменения модели наблюдаемыми для интерфейса |
| `@Bindable` / `Binding` | Связывают элементы интерфейса с чтением и изменением состояния |
| `async` / `await` | Позволяют ожидать ответ без блокировки; после await состояние могло измениться |
| `throws` / `try` / `catch` | Обозначают возможность ошибки, вызов операции и обработку ошибки |
| `defer` | Выполняет завершающий код при выходе, включая выход из-за ошибки |
| `protocol` / `any` | Позволяют заменить реализацию сети и хранилища в тестах |
| `Sendable` | Обозначает безопасную передачу значений между областями изоляции |
| `@MainActor` | Изолирует изменяемое состояние моделей экранов |
| `@concurrent` | Выносит сетевой сценарий и декодирование за пределы actor вызывающего экрана |
| `actor` / `@ModelActor` | Изолируют SwiftData и общий сервис избранного |

`async` сам по себе не означает выполнение на фоновом потоке. Подробнее:
[Swift Concurrency](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/concurrency/).

Запросы статуса избранного могут завершаться в обратном порядке. Номер
`favoriteStatusRequestID` и проверка ID цитаты не позволяют устаревшему ответу
изменить новый экран. Ошибка статуса не заменяет более важное сообщение о загрузке.

При сохранении заметки `updateNote` возвращает false, если сама запись не удалась:
редактор остаётся открыт. Если запись успешна, но обновление списка не удалось,
метод возвращает true — заметка уже сохранена.

## Форматирование, сборка и тесты

Основа оформления — [Google Swift Style Guide](https://google.github.io/swift/).
Конфигурация `.swift-format` задаёт отступы в 2 пробела и предел 100 символов.
Используется официальный [swiftlang/swift-format](https://github.com/swiftlang/swift-format).

Команды выполнять из `ITMO-iOS-2026/Lab7/ZakharchukAleksandr4141` на Mac с Xcode,
поддерживающим deployment target 26.5 и используемые возможности Swift.

```sh
xcodebuild -version
xcrun swift-format --version
xcrun swift-format lint --configuration .swift-format --strict --recursive QuoteOfTheDay QuoteOfTheDayTests QuoteOfTheDayUITests
xcrun swift-format format --configuration .swift-format --in-place --recursive QuoteOfTheDay QuoteOfTheDayTests QuoteOfTheDayUITests
xcodebuild -project QuoteOfTheDay.xcodeproj -target QuoteOfTheDay -configuration Debug -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
xcodebuild -project QuoteOfTheDay.xcodeproj -target QuoteOfTheDay -configuration Release -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
```

После форматирования повторить lint. Второй запуск форматтера должен оставить файлы
неизменными. Принудительное извлечение постоянного URL, копирование конфигурации через
NSCopying и `try!` в Preview имеют пояснения рядом с кодом.

В проекте ровно 4 теста на XCTest; прежние тесты на Swift Testing удалены.

- `QuoteOfTheDayTests`: 2 unit-теста — сохранение цитаты и даты с чтением через
  новый экземпляр хранилища; очистка цитаты с сохранением остальных настроек.
  Вместо настоящего UserDefaults используется `UserDefaultsMock`, который хранит
  значения в словаре в памяти и записывает вызовы удаления ключей. Общая подготовка
  вынесена в `setUp`, освобождение зависимостей — в `tearDown`.
- `QuoteOfTheDayUITests`: 2 UI-теста — смена текста и автора цитаты; добавление
  цитаты в избранное и её удаление с проверкой списка через интерфейс.

UI-тесты запускают Debug-приложение с аргументом `--ui-testing`: вместо API
используются две фиксированные цитаты, SwiftData хранится в памяти, а отдельный
домен UserDefaults очищается при запуске. Обычный запуск использует API и постоянную базу.
Обе тестовые цели включены в общую схему `QuoteOfTheDay`.

Для запуска выбрать схему `QuoteOfTheDay` и симулятор, затем Product → Test.
Или определить UUID устройства и выполнить:

```sh
xcrun simctl list devices available
xcodebuild -project QuoteOfTheDay.xcodeproj -scheme QuoteOfTheDay -destination 'platform=iOS Simulator,id=SIMULATOR_UUID' test
```

Заменить `SIMULATOR_UUID` на UUID доступного устройства с подходящей версией iOS.
Вручную проверить загрузку, повтор после ошибки, авиарежим с сохранённой цитатой и без неё,
закрытие экрана во время загрузки, избранное, редактирование заметок и Preview.

В текущей Windows-среде Swift, swift-format и Xcode недоступны. Компиляция, тесты,
строгий lint и ручные проверки на симуляторе здесь не выполнялись.
